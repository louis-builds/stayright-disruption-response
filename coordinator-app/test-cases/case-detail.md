# CaseDetailScreen 测试用例

## 1. 基本信息展示
- 1.1 加载中显示居中 loading 指示器
- 1.2 加载完成后显示客人昵称、扰动标题、酒店名、状态标签、优先级标签、确认号、入住/离店日期
- 1.3 内容出现有淡入过渡

## 2. 拨打电话
- 2.1 点击 "Call Guest"/"Call Hotel" 按钮发起通话,发起中显示 loading 指示器且两个按钮互斥禁用
- 2.2 离线状态下两个按钮均禁用
- 2.3 通话发起成功后跳转到 InCall 页面
- 2.4 按下按钮有按压态反馈

## 3. 通话历史
- 3.1 存在历史通话记录时显示 "Call History" 卡片,列出通话方向/状态/时间
- 3.2 无历史记录时不显示该卡片

## 4. 转人工复核(EscalationReviewCard)
- 4.1 案件未被转人工时,该卡片不显示
- 4.2 已转人工且尚未复核时,显示转人工原因(英文翻译后文案,不出现中文原文)、"Reasonable"/"Not reasonable" 两个选项
- 4.3 选择 "Not reasonable" 后,下方显示原因输入框,输入框为空时提交按钮保持禁用
- 4.4 选择 "Reasonable" 时提交按钮直接可用(无需额外输入)
- 4.5 点击提交,按钮显示 "Submitting…" 状态且不可重复点击
- 4.6 提交成功后卡片切换为只读展示态,显示 "Reviewed: Reasonable" 或 "Reviewed: Not reasonable — {备注}"
- 4.7 已复核过的案件重新进入页面,直接显示只读态,不再显示可编辑表单

## 5. 会话(Guest Conversation / AI Conversation)
- 5.1 两个 tab 可切换,当前 tab 高亮
- 5.2 "Guest Conversation" tab 下方显示消息合成框和发送按钮; "AI Conversation" 为只读,不显示合成框
- 5.3 消息列表为空时显示 "No messages yet"
- 5.4 消息较多时列表本身可独立滚动(不依赖外层页面滚动条),即消息区域是可滚动容器而非被截断
- 5.5 在合成框输入文字后 "Send" 按钮从禁用变为可点击
- 5.6 离线状态下 "Send" 按钮禁用
- 5.7 点击发送后,输入框立即清空,按钮短暂显示 "…" 状态
- 5.8 发送成功后新消息出现在列表中

## 6. 改订方案(Rebooking Options)
- 6.1 加载中显示 loading 指示器
- 6.2 无方案时显示 "No options yet"
- 6.3 有方案时逐条显示方案类型、可用性、是否已被客人选中、是否已锁定
- 6.4 点击 "Regenerate" 触发重新生成,期间按钮显示禁用态,同时 "Push to Guest" 按钮同步禁用
- 6.5 点击 "Push to Guest" 触发推送,按钮文案变为 "Working…"

## 7. 结案(CloseCaseCard)
- 7.1 案件未关闭时显示 "Close Case" 入口按钮
- 7.2 案件已关闭(status === "closed")时不显示该入口
- 7.3 点击 "Close Case" 展开表单,显示结案原因选项和结果总结输入框
- 7.4 未选择原因或总结为空时,"Confirm Close" 按钮禁用
- 7.5 都填写后按钮可点击,点击后显示 "Submitting…"
- 7.6 提交成功后表单收起,恢复为初始的 "Close Case" 入口按钮(等待父级数据刷新后案件状态会变为已关闭)

## 8. 交互反馈
- 8.1 所有可点击元素(选项 chip、tab、按钮)按下时均有可见的透明度/背景变化反馈
